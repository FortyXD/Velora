# Developing Velora

Velora targets Arch Linux with Hyprland's Lua configuration and the Quickshell `ii` shell. The project is hosted at `FortyXD/Velora`.

## Source layout

| Path | Purpose |
| --- | --- |
| `velora` | Shell entry point; resolves its checkout even when invoked through a symlink |
| `scripts/velora.py` | Component selection, preflight, package reconciliation, journals, update checks and updates |
| `scripts/install.sh` | Configuration linking and Dolphin integration |
| `packaging/arch/PKGBUILD.in` | Arch package recipe template |
| `scripts/builds.py` | Source recipes and Velora package builds |
| `scripts/runtime.py` | Writable configuration refresh for package installs |
| `dependencies/arch.toml` | Official and AUR dependencies grouped by component |
| `dependencies/python/` | Python dependency declarations and locked versions |
| `dots/.config/quickshell/ii/` | Shell services, widgets, settings, assets and translations |
| `dots/.config/hypr/` | Hyprland Lua configuration and supporting scripts |
| `dots/.config/hypr/custom/` | Local overrides and settings generated by the shell |
| `dots/.config/illogical-impulse/config.example.json` | Shared shell defaults without runtime user data |
| `dots/.local/share/` | Icons, file manager actions, helper scripts and service definitions |
| `home/` | zsh and tmux entry files |
| `dots-extra/` | Optional application configurations and font sets |
| `tests/` | Isolated installer and updater regression tests |
| `docs/reference/upstream-file-map.yaml` | Historical upstream file map retained for migration reference; not used by Velora |

The former multi-distribution installer, its local metapackages, and Fedora, Gentoo and Nix installation support have been removed. `install.sh` and `setup` are compatibility entry points for the Velora CLI.

## Editing the desktop

Edit files under `dots/.config/`. Installed links expose those changes to the desktop. The shell's live `config.json` is excluded from Git; edit `config.example.json` to change defaults for new users. Existing user settings are preserved during installation.

```bash
hyprctl reload
qs kill -c ii
qs -d -c ii
```

Keep the `ii` configuration identifier and existing internal compatibility paths unless implementing and testing a migration. Use **Velora** in user-facing project identity.

## Validation

```bash
python3 -m unittest discover -s tests -v
bash -n velora install.sh setup scripts/install.sh
./velora components
./velora install --dry-run --skip-packages
```

Tests use temporary repositories and configuration roots. They must not install system packages, access a real remote, or change the developer's desktop. Run actual package installation and visual checks separately on Arch before publishing a release.

New installer messages, diagnostics, comments, and technical documentation should be written in English. Preserve third-party license notices and update `licenses/README.md` when adding components.

## Working with the repository

Review `git diff` before publishing: linked configuration directories can contain local paths or runtime-generated changes. Commit intended local edits before using the updater. Merge upstream improvements deliberately and test them with Velora's settings and installation workflow.
